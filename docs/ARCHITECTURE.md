# 아키텍처

## 전체 그림

이 저장소는 시온 아크 플랫폼의 **프런트엔드 프로토타입**이다. 최종 형태는 총회 신학통계과의
신학부 대시보드(제작 중)를 상위로 두고, 행정 지침 대시보드와 이 강사·전도사 AI 대시보드가
결합되는 통합 구조다. 그래서 처음부터 다음 경계를 지킨다.

- 본문 화면은 셸(`src/shell/**`) 없이도 동작하게 결합도를 낮게 유지 — 상위 대시보드 임베드 대비
- 세션 발급은 `src/lib/auth.tsx` 한 곳 — SSO 확정 시 이 모듈만 교체
- 데이터 접근은 `src/lib/store.tsx` 한 곳 — API 연동 시 이 모듈만 교체

## 디자인 시스템

시안: `Design/`(Next.js + shadcn 대시보드 템플릿, 녹색·화이트). 스택이 달라 컴포넌트를
그대로 쓰지 않고 **디자인 토큰과 레이아웃 패턴만** 이식했다.

- 색: `src/index.css`의 `@theme`에 oklch로 정의. `zion-*`(**네이비 주색** — 2026-08-10에
  녹색 hue 155에서 남색 hue 261로 옮겼다) · `gold-*`(보조 강조) · `surface`/`ink`/`ink-soft`.
  **팔레트를 바꿀 일이 생기면 이 파일만 고친다** — 그 덕에 색 전환이 `@theme` 한 곳 수정으로
  끝났고 화면 파일은 한 곳도 안 고쳤다
- 사이드바는 흰 배경 + 활성 항목만 네이비 pill(그림자). 본문 배경은 옅은 남빛 화이트
- 카드는 `rounded-card`(1rem) + 옅은 테두리 + hover 시 그림자 상승
- 진입 애니메이션 `animate-slide-in-up`. 화면 전환은 **View Transitions**로 본문만 페이드
- 금색(`gold-*`)은 **우수 교안 · NEW 뱃지 · 선교센터 핀**에만 쓴다 — 나머지 강조는 네이비

### 다크 모드 (2026-08-11)

`[data-theme="dark"]`가 **팔레트 변수를 갈아 끼운다.** 화면 파일에 `dark:`를 뿌리지 않는다.
토큰이 글자와 면을 겸하므로(`text-zion-700`은 밝아야 하고 `bg-zion-700`은 어두워야 한다)
**변수는 글자 쪽에 맞춰 뒤집고, 진한 면으로 쓰는 유틸리티만 따로 되돌린다.**
진한 배경으로 쓸 수 있는 클래스 목록은 `CLAUDE.md` 화면 규칙에 있다.
밝은·어두운 두 화면 모두 WCAG AA(4.5)를 통과한 상태다.

### 화면 위에 띄우는 것 (2026-08-13)

모달 · 팝오버 · 시트는 **`src/components/Portal`로 감싸 `<body>` 밑에 그린다.**
`main`이 `view-transition-name` 때문에 쌓임 맥락을 만들어, 그 안에 두면 `z-50`을 줘도
헤더에 눌린다. `content-visibility`·`transform`이 `fixed`를 가두는 문제도 함께 풀린다.

### 반응형

현장에서 휴대전화로 자료를 여는 경우가 많아 좁은 화면을 1급으로 다룬다. 기준선은 `lg`(1024px).

- `lg` 미만: 사이드바가 **드로어**로 바뀐다 (상단 햄버거 → 슬라이드 + 오버레이, 화면 이동 시 자동 닫힘,
  열린 동안 뒤 본문 스크롤 잠금). `lg` 이상은 기존대로 272px 고정
- 목록+본문 2단 구성(자료실·교안·시리즈)은 `md` 미만에서 1단으로 쌓이고, 목록 높이를 42vh로 줄여
  본문이 화면 밖으로 밀리지 않게 한다
- 탭 줄은 `overflow-x-auto` + 항목 `shrink-0` — 좁아도 줄바꿈 없이 옆으로 넘긴다
- 출석 표는 표 자체만 가로 스크롤(`min-w-[560px]`) — 페이지 본문은 절대 옆으로 밀리지 않는다
- 검증: 전 화면에서 `body.scrollWidth - documentElement.clientWidth <= 0` (가로 넘침 0) 확인.
  ⚠️ `===`가 아니다 — `scrollbar-gutter: stable` 탓에 짧은 화면은 본문이 더 좁다

**공통 규칙은 `src/index.css`에 한 번만 둔다** — 한글 줄바꿈, flex/grid 자식의 `min-width` 해제,
iOS 입력 확대·`vh`·노치 대응 등. 화면 파일에서 되풀이하지 않는다.
상세한 규칙과 확인 방법은 [RESPONSIVE.md](RESPONSIVE.md).

그 밖에 마이페이지(`/my`)가 헤더에 있다. 외부 매체(말씀광장·천지일보)는 새 탭으로 연다.

⚠️ **2026-08-13에 화면 둘을 없앴다** — 「관찰 필요」(`/signals`)와 「사명자 심방 도우미」(`/care`).
경로는 지우지 않고 리다이렉트로 남겼다(북마크). **`lib/attendance-signals.ts`는 남는다** —
등급 판정과 수강생 상세의 「주의 포인트」가 그 값을 쓰므로 화면만 걷어낸 것이다.

⚠️ **자료실 구획은 2026-08-13에 폐지됐다.** 「강사 도우미 자료실 / 외부 자료실」 두 갈래가
없어지고 **폴더 한 줄기**가 됐다 — 「외부 자료실」은 없던 개념이고, 외부 매체는 자료에 붙는
참고 링크였다. `LibrarySection` 타입과 `section` 필드는 **저장된 값 때문에 남겨 두었을 뿐
읽는 곳이 없다**(불변식 10). 자료 목록·상세·등록 몸통은 `src/components/FolderLibrary.tsx`
한 벌을 자료실(`Library`)과 강의 도우미(`TeachingLibrary`)가 나눠 쓴다.

⚠️ **외부 매체는 사이트 안에 띄울 수 없다 — 새 탭으로 연다.** 두 사이트가 `X-Frame-Options`로
다른 사이트 안에서의 표시를 막아 두어, iframe을 쓰면 실제 브라우저에서 "이 콘텐츠는 차단되어
있습니다"가 뜬다. 우리 쪽 설정으로 풀 수 있는 문제가 아니다.
(개발용 인앱 브라우저는 이 정책을 무시해 통과한 것처럼 보인다 — **임베드 가능 여부는 반드시 실제
브라우저에서 확인할 것**. 이 함정으로 한 번 잘못 판단한 적이 있다.)

사이트 안 표시가 필요해지면 **백엔드 프록시**가 조건이다 — 서버가 대신 받아 와 우리 도메인으로
내려주면 브라우저가 같은 출처로 보아 표시된다. 착수 조건과 방법은 `docs/HANDOFF.md`에 적어 두었다.

내비 정의는 `src/shell/nav.ts` 한 곳. 새 화면은 여기에 항목을 추가한다.

내비는 3단이다 — **대주제 → (하위 묶음) → 항목**.
- 대주제는 **한 번에 하나만 열린다** (다른 대주제를 누르면 이전 것이 닫힘)
- 하위 묶음(초등·중등·고등)은 **여럿 동시에 열려 있어도 된다**. 열림 상태는 브라우저에 유지
- 하위가 없는 대주제는 `to`만 주면 접기 없이 바로 이동한다 (공지사항·총회장님 어록)

## 데이터 흐름 (현재 → 목표)

```
현재 (프로토타입)
  화면 ← useStore() ← localStorage (시드 포함)
  화면 ← cohort-mock.ts (가상 17명, 이중 분포)

목표 (운영)
  화면 ← useStore() ← app/api/library-materials · workspace-entries (D1)
  화면 ← attendance-adapter ← 읽기 전용 출결 시트 (추후 QR 시스템으로 어댑터만 교체)
```

수강생 키는 고유 ID가 없는 원본에 대비해 `교회|기수|분반|이름` 임시 키를 쓴다.
동명이인은 검토 목록으로 분리한다(원 저장소 규칙).

## Ask AI

`src/shell/AskAiBar.tsx` + `src/lib/search.ts`. 현재 로컬 키워드 검색으로 교안·에니어그램·
시리즈·자료실·공지·어록을 검색하고 **출처를 함께 표시**한다. AI API 연결 시에도:

- 검색 대상은 공통 교육 영역만 — 수강생 개인정보(차트·상담·출결 원문)는 입력 금지
- 답변에 출처 표시 유지
- aria-live 영역은 상시 렌더

## 대시보드 설계 지침

전체 현황은 **평균이 아니라 분포**를 보여준다. 예시 기수 실측: 출석률 97~100% 8명 /
50~96% 0명 / 13~49% 9명 — 중간이 없는 이중 구조가 첫 화면에서 드러나야 한다.
저녁 대면 비중(약 45%)은 보강 편성 신호로 함께 표시한다.
