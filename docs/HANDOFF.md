### 소주제 접기 (2026-08-05)

긴 자료를 통글로 내리읽지 않도록 **소주제 단위 아코디언**을 넣었다 (`src/components/Accordion.tsx`).
- 경계 판정은 `splitSections()` (`src/lib/markdown.tsx`): `##` 헤딩 · `[핵심]`류 짧은 표제 · `◈ 결론`

**사이드바도 같은 방식**(`src/shell/Sidebar.tsx`) — 3단이다: 대주제 → 하위 묶음 → 항목.
- **대주제는 한 번에 하나만 열린다** (다른 대주제를 누르면 이전 것이 닫힘)

  `localStorage: zion_ark_nav_open_sub`에 유지된다
- 현재 화면이 속한 대주제는 자동으로 펼치고, 접었을 때는 점으로 위치를 알린다
- 하위가 없는 대주제(공지사항·총회장님 어록)는 `to`만 주면 접기 없이 바로 이동한다

어록 화면 구성: **상단 = 검색·뽑기 / 하단 = 전체 주제 아코디언**(주제 98개, 눌러서 펼침).

주제 하나에 어록이 많으면(최대 148건) 주제 안에서 30건씩 나눠 보여 준다.

#### "팀원에게는 옛 버전이 보인다" — 확인 순서 (2026-08-06)

원인이 넷이고 증상이 같다. **위에서부터 하나씩 지운다.**

1. **사이드바 하단 「빌드 …」 시각을 서로 대 본다.** 이걸 넣은 이유가 이 진단이다.
   팀원 화면의 시각이 재배포보다 이르면 2·3번, 같은데도 내용이 옛것이면 4번이다
2. **공유 창에서 최신 버전을 다시 지정했는지.** 재발행해도 **공유 링크는 예전에 지정한
   버전에 그대로 묶여 있다.** 링크 주소가 같아 배포된 것처럼 보이는 것이 함정이다 —
   재발행할 때마다 공유 창에서 최신 버전 지정 + 공개 범위를 다시 확인한다
3. **팀원 브라우저 강력 새로고침** (`Ctrl`+`Shift`+`R` · 모바일은 탭을 닫았다 열기)
4. **데이터가 옛것인 경우** — 화면 코드는 최신인데 자료가 안 보이는 유형이다.
   프리뷰 데이터는 localStorage에 남아, 한 번 열어 본 사람에게는 그 뒤에 추가된 예시가
   들어가지 않았다. `load()`가 **빠진 시드만 id로 대조해 덧붙이도록** 고쳤다(2026-08-06).
   그래도 이상하면 그 브라우저에서 `zion_ark_` 로 시작하는 키를 지우고 새로고침한다

**빌드 쪽에서 조용히 어긋나던 지점도 막았다**: `build-preview.mjs`가 `dist/assets`를 훑어
첫 `.js`를 집었다. 지금은 빌드가 폴더를 비워 우연히 맞았지만, 옛 산출물이 하나라도 남으면
**빌드는 성공하고 화면만 옛것이 된다.** 이제 `dist/index.html`이 가리키는 파일을 읽고,
어느 번들을 실었는지 콘솔에 찍는다

#### 항구 해결 — GitHub Pages 자동 배포 (2026-08-06 추가)

팀원의 옛 버전 문제가 재발했고, 원인은 위 2번(공유 링크의 버전 고정)으로 확정됐다.
**아티팩트 공유는 공유 창에서 지정한 버전에 묶이며, 재발행해도 자동으로 앞으로 가지 않는다.**
이건 claude.ai 공유 화면의 동작이라 코드로 자동화할 수 없다.

그래서 push마다 같은 주소가 항상 최신을 가리키는 **GitHub Pages 배포**를 붙였다
(`.github/workflows/deploy-pages.yml`). 주소: **https://qtg002505.github.io/zion-ark/**
(2026-08-06 저장소 `qtg002505/zion-ark` 생성·푸시·Pages 활성·main 보호 규칙까지 완료.
배포 성공과 실제 화면 표시를 확인했다.)

- 프리뷰와 같은 이유로 **해시 라우팅 + 상대 경로**(`--base=./`)로 빌드한다
  (Pages는 하위 경로 서비스 + 서버 라우팅 없음)
- `index.html`에 `noindex, nofollow`를 넣었다 — **정식 운영 배포로 전환할 때 지운다**
- 1회 선행 조건: 저장소 **Settings → Pages → Source = "GitHub Actions"** (리드가 직접)
- 이후 흐름: `git push` → Actions 빌드(약 2분) → 링크 자동 갱신. 수동 재지정 없음
- Pages가 정착하면 **아티팩트 발행은 중단**한다 — 두 채널을 같이 두면 어느 쪽이 최신인지
  다시 헷갈린다

한계(리드에게 고지함): 링크를 아는 사람은 로그인 없이 접근 가능(시범 로그인은 인증이 아님),
무료 Pages는 public 저장소 전제, 반영에 빌드+CDN 캐시로 몇 분 지연, localStorage 데이터는
각자 브라우저별(팀원 간 등록 자료 비공유 — 백엔드 연동 전 한계).

### 2026-08-06 회의 반영

원문은 `docs/decisions/`에 있다 (`ORG_CHART.md` · `2026-08-06_회의메모.md`).
**착수 전 `docs/decisions/OPEN_QUESTIONS.md`를 먼저 볼 것** — 답 대기 중인 항목이 있다.

**권한 변경 — 이것이 가장 큰 변화다**
- **전도사 `division` → `cohort`**. 강사와 같은 범위, 담당 기수 전체를 본다
- **분반은 더 이상 권한 경계가 아니다.** `visibleDivisions()`는 전 분반을 돌려준다.
  `division` 스코프 값과 `divisions` 데이터는 스키마에 남긴다 — 지우면 후방 마이그레이션(불변식 10)
- 관리직(신학부장 이상)은 담당 기수가 없다 → 착지 화면이 전체현황, 실무직은 기수현황
  (`landingPath()`. `/`는 분기 전용이고 전체현황 실제 경로는 `/overview`)
- ⚠️ 백엔드 연동 시 **401·403 테스트가 뒤집힌다** — 전도사가 담당 기수 내 타 분반을
  조회하면 종전 403이었으나 이제 **200이어야 한다**

**화면 변경**
- 전체현황 = 점검자용 요약. 출석 분포·대면 시간대를 **기수현황으로 옮겼다**.
  기수 일정(개강·종강예정·새신자교육)을 추가했다
- 기수현황에 탭 둘 추가 — **주간 흐름**(주별 출석률 + 지파 최근 3개 기수 평균 기준선,
  막대를 누르면 사유·극복 표시) · **기수 비교**(지파 내 / 12지파 전체, 총회 범위만 전체 열람)
- **수강생 관리 도우미**를 대카테고리로 승격 (수강생 목록 · 관찰 필요 · 성향 참고)

### 카테고리 확정 구조 (2026-08-06 리드)

내비를 리드가 준 순서 그대로 다시 짰다 (`src/shell/nav.ts`). 순서·묶음은 **임의로 바꾸지 않는다.**

1. **우리 기수현황** — 기수 현황 · 기수 주간계획 · 전체 현황
   (관리직은 담당 기수가 없어 「전체 현황」을 보므로 같은 묶음에 둔다)
2. **수강생 관리·상담 도우미** — 수강생 목록 · 관찰 필요 · 성향 참고 · **상담 사례**
   (상담 사례를 강사 도우미에서 이리로 옮겼다)
3. **강사 도우미** — 개강 초반(개강 세미나 · 성경 밭갈이 · 예배설교) · 초등 · 중등 · 고등
   + 직속 항목 「강의 자료 모으기」
4. **전도사 도우미** — 분반 자료 · 보강 자료(영적전환 · 신심심기 · 환경정리 · 선악과 ·
   이면유월 보강 · 신앙인창조 · 사명자 양성)
5. **자료실** — 신천지도서(요한계시록 실상 · 천지창조 · 예그행) + 영인지 · 성경기초상식 ·
   하나님에 대한 필요성
6~9. 공지사항 · 총회장님 어록 · 말씀광장 · 천지일보

**구현 시 판단한 것**
- 「개강 세미나·성경 밭갈이·예배설교」는 종전에 자료실 아래 있었다. 이제 **강사 도우미 ›
  개강 초반**에서 열고, 자료실 대메뉴에는 신천지도서와 외부 자료만 남겼다.
  자료 자체는 같은 `instructor` 구획이고 **내비 위치만 바뀐 것**이다 — 구획을 새로 만들면
  `LibrarySection` 계약이 바뀌므로 그렇게 하지 않았다
- 대신 폴더 정의를 `INSTRUCTOR_EARLY_FOLDERS`(강사 개강 초반)와
  `EVANGELIST_MAKEUP_FOLDERS`(전도사 보강)로 나눠 두고 `LIBRARY_FOLDERS`가 합친다.
  자료실 화면의 폴더 목록도 같은 이름으로 갈라 보여 준다 — 열 개를 평평하게 늘어놓으면
  누가 쓰는 자료인지 구분이 안 된다
- **사이드바가 하위 묶음을 직속 항목보다 먼저 그리도록 바꿨다.** 확정 구조에서 묶음이
  앞서기 때문이다 (자료실 › 신천지도서 → 영인지…)
- ⚠️ 보강 자료 7개 폴더는 **아직 자료가 없다**(0건). 폴더 자리만 만들어 둔 상태다
- ⚠️ 리드 표기는 "성경기초 상식"(띄어쓰기)이나 코드 값은 기존 `성경기초상식`을 유지했다.
  문자열을 바꾸면 이미 그 폴더로 저장된 자료가 폴더에서 빠진다. 표기를 맞춰야 하면 알려 달라

회의 후 막혀 있던 다섯 항목에 답이 왔다. **확정값은 `CLAUDE.md`에 옮겼고 재질문하지 않는다.**

- ⚠️ **"외부"는 자료의 성격이지 공개 범위가 아니다.** 둘 다 로그인해야 열리므로

### 반응형 · 크로스 브라우징 (2026-08-05)

PC·Android·iOS에서 같게 보이도록 **공통 규칙을 `src/index.css`에 모았다**.
상세는 `docs/RESPONSIVE.md`. 화면 파일마다 되풀이하지 않는다.

밖에서 재현되던 증상과 원인:
- **텍스트가 세로로 찢어짐** — flex·grid 자식의 `min-width: auto` 때문에 한 칸이 부모를 밀어내고
  옆 칸이 찌그러진다. `:where(.flex,.grid) > * { min-width: 0 }`로 전역 해제
  (줄면 안 되는 요소는 `shrink-0`이 그대로 이긴다)
- **iOS에서 입력칸 누르면 레이아웃 틀어짐** — Safari는 입력 글자가 16px 미만이면 화면을 확대한다.
  터치 기기에서만 입력 요소를 16px로 올렸다(디자인상 12~13px보다 커지지만 확대되는 쪽이 더 나쁘다)
- **iOS 가로 모드에서 글자만 커짐** — `-webkit-text-size-adjust: 100%`
- **목록이 화면 밖으로 넘침** — iOS는 `vh`를 주소창까지 포함해 잰다.
  `.doc-list-scroll` 유틸이 `dvh`를 우선 쓰고 미지원 시 `vh`로 되돌아간다
- 한글 줄바꿈은 `word-break: keep-all` + `overflow-wrap: anywhere` **둘 다** 필요하다

검증: 320·375·768·1280 폭에서 전 화면 가로 넘침 0, 세로 찢김 0.
공백 없는 긴 URL·긴 한글 문장을 넣어도 영역 안에서 줄바꿈됨을 확인했다.
⚠️ **iOS 특유 동작은 데스크톱 시뮬레이션으로 재현되지 않는다** — 실기기 확인이 필요하다.

### 보류 — 말씀광장·천지일보 사이트 안 표시 (백엔드 프록시 필요)

리드 요청은 "사이트 안에서 보기"였으나 두 매체가 `X-Frame-Options`로 외부 표시를 막고 있어
현재는 **새 탭으로 연다**(2026-08-05 리드 결정). 사이트 안 표시는 아래 조건이 갖춰지면 가능하다.

**착수 조건**: 백엔드(API 서버)가 붙어 우리 도메인에서 요청을 중계할 수 있을 때.
프런트 전용인 지금은 불가능하고, 정적 프리뷰(아티팩트)에서도 불가능하다.

**방법**: 서버에 중계 경로(예: `/api/external/:id`)를 두어 대상 페이지를 받아 우리 도메인으로
내려준다. 브라우저가 같은 출처로 보므로 iframe에 담긴다. 확인·주의할 점:
- 상대 매체 이용약관에 중계·재표시가 걸리지 않는지 먼저 확인 (법무·리드 판단 사항)
- 상대 페이지의 상대경로 자원(css·js·이미지)이 깨지지 않게 base 처리 필요
- 캐시를 두어 상대 서버에 부담을 주지 않게 한다

**작업이 가능해지는 시점에 리드에게 알린다** — 백엔드 연동 착수 세션에서 이 항목을 확인할 것.
