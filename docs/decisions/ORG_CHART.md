# 시온 아크(ZION ARK) 조직도와 권한 매핑

**확정일** 2026-08-06 · **출처** 리드(박성훈) 구두 확정 · **기준 문서** `CLAUDE.md` v4 §4·§5 · 옵시디언 금고 `00-공통/접근권한-매트릭스`

> 이 문서는 `memberships.role_code` · `memberships.scope_type`의 **문서 기준값**입니다. 코드와 다르면 이 문서가 기준이며, 이 문서를 고치면 옵시디언 금고 `접근권한-매트릭스` · `권한-결정사항` · `현재-상태`도 함께 갱신합니다.

---

## 1. 조직 계층

조직 계층은 **총회 → 지파 → 교회 → 기수** 4단계입니다. 신학부장 이상은 **관리직**으로 담당 기수를 갖지 않고, 기수에 배정되는 것은 강사와 전도사뿐입니다.

```
총회 (national) ─────────────── 관리직 · 담당 기수 없음
├─ 총회 사명자                      ★ 총괄 — 전권
│  ├─ 총회 신학부장
│  ├─ 총회 신학서무
│  └─ 총회 신학과장
└─ 총회 서버관리자 · 정보통신부      ★ 총괄 — 전권
│
└─ 12지파 (tribe) ───────────── 관리직 · 담당 기수 없음
   ├─ 지파 신학부장 (12지파 본부교회 소속)
   └─ 지파 신학부 서무              ← 신학부장과 공통 권한
   │
   └─ 교회 (church) ──────────── 관리직 · 담당 기수 없음
      └─ 교회 신학부장
      │
      └─ 센터 기수 (cohort) ───── 실무직 · 기수 배정 있음
         ├─ 강사 1명
         └─ 전도사 여러 명
         ※ 강사 1명 + 전도사 N명 = 1기수 운영 단위
```

12지파 이름과 권역은 금고 기준값을 따릅니다: 요한 · 베드로 · 부산야고보 · 안드레 · 다대오 · 빌립 · 시몬 · 바돌로매 · 마태 · 맛디아 · 서울야고보 · 도마.

## 2. 역할 코드 매핑 (`memberships.role_code`)

| 조직도상 직책 | `role_code` | `scope_type` | 기수 배정 | 열람 범위 |
|---|---|---|---|---|
| 총회 신학부장 | `headquarters_admin` | `national` | 없음 | 전권 — 12지파 전체 |
| 총회 신학서무 | `headquarters_admin` | `national` | 없음 | 전권 |
| 총회 신학과장 | `headquarters_admin` | `national` | 없음 | 전권 |
| 총회 서버관리자 · 정보통신부 | `headquarters_admin`(잠정) | `national` | 없음 | **총괄 — 전권** |
| 지파 신학부장 | `tribe_admin` | `tribe` | 없음 | 해당 지파 전체 |
| 지파 신학부 서무 | `tribe_admin` | `tribe` | 없음 | 신학부장과 공통 권한 |
| 교회 신학부장 | `church_admin` | `church` | 없음 | **담당 교회 전체(8/6 확정)** |
| 강사 | `instructor` | `cohort` | **있음** | 담당 기수 전체 |
| 전도사 | `evangelist` | `cohort` | **있음** | 담당 기수 전체 — 강사와 동일(8/6 변경) |
| 콘텐츠 관리자 | `content_admin` | — | 없음 | 공통 교육 자료 |
| 보안 감사자 | `security_auditor` | 지정 감사 범위 | 없음 | 감사 로그 |

**관리직과 실무직의 구분이 화면 설계를 가릅니다.** 관리직(신학부장 이상)은 `memberships`에 `cohort` 배정이 없으므로 "내 담당 기수" 위젯이 비어 있습니다. 이들의 기본 화면은 하위 조직 전체 집계(전체현황)여야 하고, 실무직(강사·전도사)의 기본 화면은 담당 기수 상세(기수현황)여야 합니다.

**묶음말**: 금고 확정 어휘의 `사명자 = 강사 + 전도사`와, 조직도상 "총회 사명자"(총회 관리직 전체)는 서로 다른 용법입니다. 화면 문구에서 섞이지 않게 주의합니다.

## 3. 2026-08-06 변경 사항

**전도사 권한 범위 변경 — 분반 → 기수**

| 항목 | 종전 기준값 | 변경 후 |
|---|---|---|
| 전도사 `scope_type` | `division` (담당 분반) | `cohort` (담당 기수) |
| 전도사 열람 범위 | 담당 분반 수강생만 | 담당 기수 전체 — 강사와 동일 |

반영이 필요한 곳:
- `CLAUDE.md` §4 "역할별 기본 범위" 문장 — "전도사=담당 분반" → "전도사=담당 기수(강사와 동일)"
- 옵시디언 금고 `00-공통/접근권한-매트릭스` · `권한-결정사항`
- `app/access-policy.ts` · `app/org-resolver.ts`의 범위 판정
- 401·403 테스트 케이스 — 전도사가 담당 기수 내 타 분반을 조회할 때 **200이 되어야 합니다**(종전 403)

**관리직 · 실무직 구분 확정(8/6)**
- 조직 계층은 총회 → 지파 → 교회 → 기수 4단계입니다
- 신학부장 이상은 관리직이며 담당 기수를 갖지 않습니다. `memberships`에 `cohort` 배정이 생기지 않습니다
- 총회 사명자와 정보통신부는 총괄로서 전권을 가집니다

**점검자 범위 확정**
- 총회 = 12지파 전체 통합 출석현황 · 지파 신학부장 = 해당 지파 전체 출석현황
- 기존 `memberships` 스코프 판정으로 그대로 커버되므로 신규 권한 체계는 필요하지 않습니다

## 4. 불변식과의 정합성

- 불변식 1 유지: 클라이언트가 보낸 조직 ID를 믿지 않고 서버가 `memberships`와 대조합니다. 전도사 범위가 넓어져도 판정 주체는 그대로 서버입니다
- 불변식 3 유지: 담당 범위 밖 호출은 403, 무세션은 401
- `scope_type`에 `division`은 스키마에 남겨 둡니다. 분반 단위 배정이 다시 필요해질 수 있고, 제거는 후방 마이그레이션이 되어 불변식 10에 걸립니다

## 5. 계층 드릴다운 열람 권한 (8/6 확정)

| 사용자 | 볼 수 있는 범위 | 드릴다운 경로 |
|---|---|---|
| 총회 사명자 · 정보통신부 | 12지파 → 교회 → 기수 **전부** | 지파 목록 → 교회 목록 → 기수 목록 → 기수 상세 |
| 지파 사명자(신학부장·서무) | 담당 지파 내 교회 → 기수 **전부** | 교회 목록 → 기수 목록 → 기수 상세 |
| 센터 기수 사명자(강사·전도사) | **담당 기수만** | 기수 상세 (드릴다운 없음) |

**분반은 권한 경계가 아닙니다.** 열람 권한의 최소 단위는 기수이며, 전도사도 담당 기수 전체를 봅니다. `divisions` 테이블과 `division` 스코프 값은 스키마에 남기되(불변식 10 — 후방 마이그레이션 금지), 권한 판정에는 쓰지 않습니다.

## 6. 로그인 직후 기본 화면 분기 (권장안)

관리직은 `cohort` 배정이 없어 "내 담당 기수" 위젯이 구조적으로 비므로, 착지 화면을 역할별로 나눕니다.

| 조건 | 착지 화면 |
|---|---|
| `cohort` 배정 없음 + `national` | 전체현황 — 12지파 집계, 지파 카드에서 드릴다운 |
| `cohort` 배정 없음 + `tribe` | 전체현황 — 담당 지파 집계, 교회 카드에서 드릴다운 |
| `cohort` 배정 없음 + `church` | 전체현황 — 담당 교회 집계, 기수 카드에서 드릴다운 |
| `cohort` 배정 1건 | 기수현황 — 해당 기수 상세로 직행 |
| `cohort` 배정 2건 이상 | 기수 선택기 → 기수현황 |
| 관리직 + `cohort` 배정 동시 보유(겸직) | 넓은 범위 우선(전체현황). 상단에 "내 담당 기수" 바로가기 노출 |

구현 원칙:
- 착지 화면 판정은 **서버**가 `app/org-context.ts`의 스코프 해석 결과로 내립니다. 클라이언트가 보낸 view 값을 그대로 믿지 않습니다
- 착지 화면은 편의 기능일 뿐 권한이 아닙니다. 어느 화면으로 들어가든 각 API는 `memberships`로 다시 검증합니다(불변식 1). 범위 밖은 403, 무세션은 401
- 드릴다운 각 단계는 같은 집계 컴포넌트를 레벨(`national`/`tribe`/`church`)만 바꿔 재사용합니다. 레벨별로 화면을 새로 만들지 않습니다
- 초기 View 결정 분기는 `app/Dashboard.tsx`에 들어갑니다. 단일 소유자 핫스팟이므로 리드 또는 지정 소유자만 편집합니다

## 7. 전권 계정 취급 원칙

총회 사명자와 정보통신부는 전권이므로 **조직 스코프 판정이 통제 장치로 작동하지 않습니다.** 이 계정들에 대한 유일한 통제 수단은 감사 로그이므로 다음을 지킵니다.

- 전권 계정의 `counseling_read` · `counseling_write` · `counseling_export` · `chart_read` · `chart_write`는 예외 없이 `audit_logs`에 남깁니다
- `audit_logs.detail`에는 사유·건수 같은 짧은 메타데이터만 넣습니다. 상담 원문은 금지입니다(불변식 5)
- 전권이라도 출결 스프레드시트 되쓰기는 금지입니다(불변식 8). 전권은 열람 범위의 문제이지 쓰기 금지의 예외가 아닙니다
- `security_auditor`는 전권 계정의 행위를 검토하는 역할이므로, 정보통신부 계정과 동일인에게 함께 부여하지 않는 편이 안전합니다
