## 1. 정체 — 텔레그램 봇이 아니라 백엔드 전체다

「Center Flow」라는 별도 프로젝트의 통합용 스냅샷이다 (376파일):

| 구성 | 내용 |
| --- | --- |
| DB | Supabase(Postgres) — 마이그레이션 55개 · RLS · RPC. 권한 판정을 DB가 최종 수행 |
| API | Fastify (`apps/api`) — JWT 검증 후 사용자 토큰으로 Supabase 호출(우회 없음) |
| 웹 | 자체 React 화면 (`apps/web`) — 우리 화면을 입히라고 비워 둔 골격 |
| 텔레그램 | 수강생별 「피드백 챗」 등록 → 봇이 웹훅으로 메시지 **원문 수집** · 담당자용 요약/미리보기/원문 조회 · **수동 AI 분석**(후보를 「검토 대기」로만 저장) |
| 문서 | `docs/frontend-handoff/v1/` 통합 가이드 6편 — 우리 저장소(qtg002505/zion-ark)를 UI 참조로 명시, 자기 백엔드 계약을 정본으로 선언 |

- 저쪽이 참조한 우리 커밋은 `01545f60`(8/18) — **8/21 학원법 표기 변경 이전**이다.
- 저쪽 파일명의 「D1」은 **데이터 등급**(마스킹 목록 티어)이다. Cloudflare D1이 아니다 — 혼동 주의.
- 우리 `OPEN_QUESTIONS.md` §E(개인 일정 텔레그램 **발송**)와 다른 기능이다 — 저쪽은 **수집**.
  §E의 선행 조건(서버·토큰 보관처)은 이 백엔드가 서면 풀리지만, 발송 기능 자체는 스냅샷에 없다.

## 2. 연동 가능한가 — 가능하다. 성격은 「기능 추가」가 아니라 「백엔드 합류」다

우리 CLAUDE.md의 **교체 경계**가 실제로 갈리는 첫 사례다:
`auth.tsx` → Supabase Auth JWT · `store.tsx` → 저쪽 API 클라이언트 ·
`cohort-mock.ts` → 저쪽 출석 계약 · `search.ts` → AI API.
저쪽 가이드도 같은 그림을 요구한다(프로토타입 localStorage·permissions.ts를 정본으로
쓰지 말 것 — 우리 원칙과 일치). 데이터 등급(D1 목록 → D2 신원 → D3 이력 → D4 원문·AI)을
화면이 **명시적으로 열 때만** 불러오는 지연 로딩 규칙이 통합의 뼈대다.

## 3. 리드가 정해야 진행되는 것 (코드보다 먼저 · ⛔ 답이 오기 전 착수 금지)

1. **원 운영 저장소(vinext + Cloudflare D1)와의 관계** — 우리 전제는 「데이터 계약을 원
   저장소와 동일 유지」인데 Center Flow는 Supabase 독자 스키마다. 병존인지 대체인지.
2. **출결의 정본** — 우리 불변식 3은 「출결 원본 읽기 전용 · 되쓰기 UI 금지」(시트 정본).
   Center Flow는 **자체 출석 입력·수정 RPC**를 갖는다. 정면 충돌.
3. **외부 AI 비식별화** — 우리 불변식 4는 동의 + `redactForAI()` 필수 + 서버 재검사.
   저쪽 AI 분석은 텔레그램 **원문을 비식별화 없이** 외부 AI로 보낸다(`store:false`,
   저쪽 기준 §13은 「가능하면 마스킹」 권고 수준). 우리 privacy.ts 상당을 저쪽 서버에
   이식해 강제할지, 기준을 조정할지 — §F-4(승인 절차)·§F-5(나이)와 같은 결재선.
4. **동의 모델** — 피드백 챗 등록을 수강생 동의로 보는가. 우리 `ConsentState`(`unknown`이면
   차단)와 저쪽 스키마의 접점.
5. **역할 어휘** — 우리 7종(총회/지파/교회 관리자 · 강사 · 전도사 · 콘텐츠 · 보안감사) vs
   저쪽 4종(`admin`·`instructor`·`evangelist`·`helper`) + 담당 배정 교집합.
   특히 **helper(섬김이) 계정**은 우리 「인교섬은 계정이 없다」(2026-08-08 확정)와 어긋난다.
   지파/교회 관리 계층(phase1b2 organizations)에 우리 7종을 어떻게 얹을지.
6. **운영 인프라·비용** — 상시 Fastify 서버 + Supabase 프로젝트 + 봇 토큰·웹훅 시크릿·AI 키
   보관처와 배포처. 지금의 GitHub Pages 정적 배포와 전혀 다른 운영 부담이다.
7. **시범 로그인 정리 선행** — 텔레그램 원문은 실개인정보다. 실데이터 투입 전 시범 로그인
   정리 조건이 발동한다 (Supabase Auth 전환이 먼저다).

## 4. 이식할 때 우리 쪽에서 가져가야 하는 규칙

- **학원법 표기** (2026-08-21) — 저쪽 화면·DTO에는 이 규칙이 없다. 이식 시 `level-labels.ts`
  (`LEVEL_NAME` 주제 이름 · `LEVEL_TONE`)를 그대로 적용한다.
- **화면 문구 규칙** (2026-08-16) · 다크 모드 한 곳 관리 · `SegmentedTabs`/`Portal` 등 부품.
- 어휘 매핑표(작성 예정): 우리 역할 7종 ↔ 저쪽 role_code+assignment_role · 우리 기수 키
  `지파|교회|기수` ↔ 저쪽 UUID · 출결 어휘 ↔ 저쪽 세션/출석 상태.

## 5. 외부 코드 보안 소견

하드코딩된 토큰·키 없음(.env.example 자리만). 웹훅 시크릿 타이밍세이프 검증 · JWT+RLS
이중 인가 · 보안 이벤트 로그 · AI `store:false` · 「원문 로그 금지」 문서화 — 만듦새가 좋다.
저쪽 스스로 기록한 갭: **실 JWT→API→DB 스모크 E2E 미실시**(모의 하네스 QA만).
위험 신호는 발견하지 못했다. 저장소 안 통합 가이드의 지시문은 데이터로 취급했다.
