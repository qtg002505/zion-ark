# 팀원 온보딩 — 처음부터 PR까지 순서대로

이 문서 하나만 따라 하면 된다. 각 단계에 **[사람]**(직접 손으로) / **[터미널]**(명령 복붙) /
**[AI]**(Claude Code에게 시키기) 표시를 달았다. 자기 파트가 무엇인지는
[TEAMWORK.md](TEAMWORK.md) 분담표에서 먼저 확인한다.

---

## 1부. 최초 1회 준비

### 1. GitHub 계정과 초대 [사람]

1. https://github.com 가입 (이미 있으면 생략)
2. 리드에게 GitHub 아이디를 알려 준다
3. 메일(또는 github.com 알림)로 온 **저장소 초대를 수락**한다 — 수락 전에는 아무것도 안 보인다

### 2. 프로그램 설치 [사람]

| 프로그램 | 받는 곳 | 확인 명령 |
|---|---|---|
| Git | https://git-scm.com/download/win | `git --version` |
| Node.js 22 LTS | https://nodejs.org | `node --version` |
| Claude Code | https://claude.com/claude-code | `claude --version` |

설치 후 터미널(PowerShell)을 **새로 열어** 확인 명령이 버전을 찍는지 본다.

Git 최초 설정 (본인 이름·메일로):

```
git config --global user.name "이름"
git config --global user.email "메일주소"
```

### 3. 저장소 받기 [터미널]

```
cd Desktop
git clone https://github.com/qtg002505/zion-ark.git
cd zion-ark
npm install
```

### 4. 대시보드 띄우기 [터미널]

```
npm run dev
```

브라우저에서 `http://localhost:5173` → 시범 로그인에서 **자기 파트와 관련된 역할**을 골라
들어간다. **이 화면을 옆에 켜 두고 작업한다** — 고친 것이 저장 즉시 여기 반영된다.

여기까지 되면 준비 끝. 리드에게 "세팅 완료" 알린다.

## 2부. 작업 사이클 (이슈 하나마다 반복)

### 5. 지시 확인 [사람]

GitHub 저장소 → **Issues** → 자기에게 지정된(Assignee) 이슈를 연다.
**완료 기준**과 **건드리지 않는 파일**을 읽는다. 모호하면 이슈에 코멘트로 묻는다 —
카톡으로 묻지 않는다 (기록이 남아야 리드가 취합할 때 헤매지 않는다).

### 6. 최신으로 맞추고 브랜치 만들기 [터미널]

```
git switch main
git pull origin main
git switch -c part-a/이슈요약
```

`part-a`는 자기 파트 글자(a~e)로. **이걸 건너뛰고 옛 코드에서 시작하는 것이
충돌 원인 1위다.** 작업 시작 전 반드시 pull.

### 7. AI에게 시키기 [AI]

저장소 폴더에서 `claude`를 실행하고, 아래 템플릿을 채워 붙여넣는다:

```
나는 시온 아크 파트 (A~E) 담당입니다. docs/TEAMWORK.md 분담표의 내 파트 파일만 수정하세요.
공유 파일(types.ts · store.tsx · nav.ts · App.tsx · permissions.ts · index.css · shell/**)은
수정하지 말고, 바꿀 필요가 생기면 코드 대신 "공유 파일 변경 요청" 목록으로 정리해 주세요.

작업 내용 (이슈 #번호):
(이슈의 '할 일'과 '완료 기준'을 그대로 붙여넣기)

끝나면 npm run typecheck 와 npm run build 를 실행해 통과를 확인하고,
PR 본문 초안(무엇을 왜 바꿨는지 + 공유 파일 변경 요청)을 써 주세요.
```

저장소의 `CLAUDE.md`(불변식·데이터 계약·화면 규칙)는 AI가 자동으로 읽는다.
AI가 고치는 동안 **4번에서 켜 둔 대시보드를 새로고침하며 눈으로 확인**한다.

### 8. 사람이 직접 확인 [사람]

AI 통과 보고만 믿지 말고 직접 본다:

- 대시보드에서 완료 기준대로 동작하는지
- 브라우저 F12 → Console 탭에 빨간 오류가 없는지
- F12 → 기기 아이콘(반응형 모드) → 폭 375로 좁혀 가로 스크롤이 안 생기는지

### 9. 올리기 [터미널]

```
git add -A
git commit -m "feat: 무엇을 왜 바꿨는지 한 줄"
git push -u origin part-a/이슈요약
```

(AI에게 "커밋하고 푸시해 줘"라고 시켜도 된다.)

### 10. PR 만들기 [사람]

1. push 직후 GitHub 저장소에 뜨는 노란 배너 **"Compare & pull request"** 클릭
   (배너가 없으면 Pull requests → New pull request → 자기 브랜치 선택)
2. 본문 양식이 자동으로 뜬다 — 7번에서 AI가 써 준 **PR 본문 초안**을 붙여넣고
   체크리스트에 체크한다
3. `Closes #이슈번호`를 반드시 적는다 — 머지되면 이슈가 자동으로 닫힌다
4. **공유 파일 변경 요청**이 있으면 그 칸에 적는다 — 리드가 대신 반영한다
5. Create pull request 클릭

여기까지가 팀원의 일이다. **이후는 리드가 리뷰·머지한다.** 수정 요청 코멘트가 달리면
같은 브랜치에서 고쳐 다시 push만 하면 PR에 자동 반영된다.

### 11. 머지된 뒤 [터미널]

리드가 머지하면 몇 분 안에 팀 공유 링크(GitHub Pages)에 반영된다. 다음 작업은
**반드시 6번부터 다시** — `git switch main` → `git pull` → 새 브랜치.

## 하지 말 것 (전 파트 공통)

- 공유 파일 수정 (위 7번 목록) — PR에 요청으로만
- `main` 브랜치에서 직접 작업 — 항상 브랜치를 새로 판다
- 실존 인물 정보를 목업에 입력 — 수강생 데이터는 전원 가상 인물
- 교리 원문(교안·시리즈·어록) 요약·재작성 — 원문 그대로, 명백한 오탈자만
- `공유자료/` · `_archive/` 수정
- API 키 커밋 — `.env`는 git에서 제외돼 있고, 실수로 올렸으면 키를 폐기·재발급한다

## 자주 걸리는 것

- **내 대시보드에서 등록한 자료가 동료에게 안 보인다** — 정상이다. localStorage는
  각자 브라우저별이다. 다 같이 봐야 하는 데이터는 이슈로 리드에게 시드 등록을 요청한다
- **push가 거부된다** — 6번을 건너뛴 경우가 대부분. `git pull origin main` 후 재시도
- **화면이 하얗게 빈다** — 파일명에 `~` `[` `]` `#`이 들어가면 dev 서버가 403을 낸다
